Add the interactions runtime (#108, with #65 and #57 at the core level). `run.ask` is real for the `RunRegistry` path: core assigns the interaction id, `seq` and reply code, keeps a per-task FIFO with exactly one presented interaction, publishes `input-required` (`auth-required` for auth) through the adapter's `renderInteraction`, persists a redacted `PendingInteraction` through `RunStore` (new `putPending` / `getPending` / `listPending`) and parks the run. A reply is a second `execute()` on the same task: `handleReply` parses it against the presented interaction only (a text approval needs the reply code, stale or unknown replies are ignored with a re-prompt, unknown never approves) and the SAME `provider.run` continues. Interactions expire per kind (10 minutes, auth 30) through `registry.expire`, can be withdrawn with `AskOptions.signal`, and are canceled by cancel and by the end of the run. New `InteractionPolicy` (`interactionPolicy`, `mode: "auto" | "ask"`, `autoAnswer`; default `auto` keeps today's behaviour). The restart sweep now handles `interrupted` records: `provider.reattach(pending, runs)` for interactions with a handle, otherwise the task fails with "server restarted". `CoreExecutor` opens a reply's stream with the Task snapshot and closes the attachment at every park; a task-store publisher writes the A2A store for runs nobody consumes. Also moves `parseInteractionReply` to the SDK-free model (still exported from the adapter) and adds `RunPublisher.interaction`. Secret answers are also removed from the stored A2A task history (`OrphanGuardTaskStore`), concurrent replies cannot break each other's stream (`registry.beginReply`), `autoAnswer` rules apply in `auto` mode too, and the per-task publisher bookkeeping and store write queues are scoped to the registry and the store (no process-global maps).
