Add steering of in-flight tasks (#109). A message sent to a RUNNING task carries a caller-chosen `delivery`: `queue` (the default; core's lane runs it as the next turn of the same task, persisted as a `QueuedMessageRecord` with the atomic `queued -> running` claim and an honest `position`), `steer` (the provider's `steer` handler returns `inserted`, `queued{handle}` or `rejected`; no handler means core queues it and says so) or `interrupt` (`abort(info, "interrupt")`, then the message is the next turn and the task stays non-terminal; no `abort` handler means a queue with the reason; an interrupt with no content parks the task in `input-required` marked `interrupted`). New `RunRegistry.deliver(taskId, message, by, request)` returns the `DeliveryResult` and is idempotent by message id (and `idempotencyKey`); every intent goes through `authorize(by, "queue" | "steer" | "interrupt", task)`. `steer` and `interrupt` are routed before the interaction reply path: they never answer an interaction (a steer waits behind it, an interrupt may preempt it). A non-final turn's result is now published as output. Over A2A, `RunEventBusManager` gives a message to a working task a private bus and `CoreExecutor` answers it with one Message carrying the result (`urn:a2a-wrapper:delivery-result:v1`), so the client never gets an error for a message that will be delivered, a blocking `message/send` returns at once and the running stream is untouched. Also `runStoreContractTests(factory)` (a reusable suite any `RunStore` can be verified against) and the S2 spike pinned as tests. `RunRegistryOptions` gains `steerTimeoutMs` and `interruptedTimeoutMs`.
