Add context binding persistence and resume after a restart (#110, part of #81; also what Codex thread resume, #100, needs once that wrapper is migrated). `run.bind(session)` now persists a `ContextBinding` (owner and tenant of the caller, timestamps, `lastUsedAt`, `session` with an `issuer` of `<provider id>@<ProviderInfo.sessionFormat ?? "1">`, so a version bump keeps every conversation) through the `RunStore`: a rebind replaces it, a bind after a cancel or from a stale turn is dropped, writes of one context are applied in call order, and `bind` throws a `TypeError` for an empty `ref` or a `meta` that cannot be stored. When a request arrives for a context core loads the binding AFTER the context's lane slot is held and hands it to the provider as `CoreRequest.session`, with these rules: another caller's (or tenant's) context is refused (task `rejected`, `CoreError.code: "forbidden"`, spec 13.1; never a silent fresh session), a binding written by another provider or session format (new optional `ProviderInfo.sessionFormat`) is discarded, never replayed and never released, an expired one (`RunRegistryOptions.bindingTtlMs`, default none) is dropped, `authorize(by, "resume", target)` stays the choke point, and a resume touches `lastUsedAt`. New `CoreError.code` `session-not-found` (`SESSION_NOT_FOUND`, `SessionNotFoundError`): a provider that cannot resume `request.session` reports it and core deletes the binding, waits for the first `provider.run` to settle (bounded by `abortTimeoutMs`; otherwise the turn fails with the code) and retries the SAME turn once with no session (never twice, never after the turn published output). New optional `ProviderExecutor.probeSession(session)` (`"alive" | "gone" | "unknown"`) used by `validateBindingsOnStart` (default `false`; `RunRegistry.sweep()` then reports `SweepReport.bindings`), and `RunRegistry.sweepBindings({olderThanMs?})` removes idle bindings older than the TTL and never those of a context with a live, parked or orphaned run. `RunStore` gains `listBindings`, `touchBinding` and a compare-and-delete `deleteBinding(contextId, ifRef?)` that now resolves a boolean (custom stores must add them; `runStoreContractTests` covers them); `ContextBinding` gains an optional `lastUsedAt`; `ExecuteInit` gains an optional `tenant` that `CoreExecutor` fills from the call context. An abort outcome of `discard` (also after a restart, through `abortOrphan`) clears the binding only when it still names the aborted session and never sends a mismatched issuer's ref to `release`.
